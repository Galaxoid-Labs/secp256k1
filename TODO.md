# TODO — closing the gap to "verified"

Written after an honest audit. The implementation is complete and the differential oracle
reports zero divergences, but several gates named in `DEVELOPMENT.md` have never run, and
some upstream test functions have no counterpart here at all.

**The current defensible claim** is: *passes 104 self-written tests including mirrors of
~50 upstream test functions; byte-identical to libsecp256k1 across fuzzed inputs on two
architectures, including MuSig2 and ellswift; passes the full Wycheproof ECDSA (463) and
ECDH (752) corpora, the official BIP340 vectors, and every BIP327 MuSig2 vector group;
enumerates the entire group on the exhaustive curves at orders 7, 13 and 199; and reports
zero findings from the valgrind constant-time harness across ten secret paths.* It is
**not** "passes libsecp256k1's tests" — see item 5, which turns out not to be achievable in
the form this document assumed.

Everything in items 1–7 runs on macOS. Items 8–9 need Linux, and **have now been run** on a
Fedora x86-64 box — see those sections for what they found and what is left.

**Prerequisite on a fresh machine.** Items 1–5 and 9 all need an upstream v0.7.1 checkout,
which is not vendored. One clone supplies the musig vectors, the wycheproof JSON, the
oracle `.a` and `tests.c`:

```sh
git clone --depth 1 --branch v0.7.1 https://github.com/bitcoin-core/secp256k1 upstream
cmake -S upstream -B upstream/build -DCMAKE_BUILD_TYPE=Release \
  -DSECP256K1_ENABLE_MODULE_{RECOVERY,ECDH,SCHNORRSIG,MUSIG,ELLSWIFT,EXTRAKEYS}=ON \
  -DBUILD_SHARED_LIBS=OFF
cmake --build upstream/build -j8
./oracle/link-lib.sh upstream/build/lib/libsecp256k1.a
```

## 1. BIP327 MuSig2 vectors — hard gate, Phase 7

**Why first:** MuSig2 is the highest-risk module in the project and has the least external
validation. It is also the cheapest to close.

Source is already local: `~/Development/secp256k1/src/modules/musig/vectors.h`, 135 cases
covering key aggregation (valid and error), nonce generation, and nonce aggregation.

- [x] Transcribe the vectors into `tests/musig/` (generated by a parser over the C header, so
      regenerating reproduces the table; unmodified). Done for key aggregation (4 valid,
      5 error), nonce aggregation (2 valid, 3 error) and nonce generation (2 cases).
- [x] Cover the error cases too — all 8 error cases pass, and the assertions distinguish
      *why* a case was rejected so a right answer for a wrong reason still fails.
- [x] Include the KeySort vectors (they are in `tests.c`'s `test_sort_vectors`, not
      `extrakeys/tests_impl.h`). Also closes `run_pubkey_sort` from item 7.
- [x] **This found a real BIP327 non-compliance.** `nonce_gen` was not implementing BIP327
      NonceGen at all — it was an invented two-stage scheme that omitted the `MuSig/aux`
      XOR of the secret key, **never hashed the signer's public key**, and used
      presence-byte framing instead of the specified 8-byte and 4-byte big-endian length
      prefixes. Nothing could see it: every signer computed the same wrong value, so the
      self-consistency test passed, and musig has no oracle coverage (item 2). Rewritten to
      the specification; both vectors now match exactly on secnonce and pubnonce.

      Omitting the public key is the part that mattered. BIP327 binds the nonce to the
      signer's key precisely so that two signers who share entropy do not derive the same
      nonce — and a shared nonce in MuSig2 leaks both secret keys.
- [x] `sig_agg` transcribed and passing — 4 valid, 1 error. Three of the valid cases apply
      chains of mixed x-only and plain EC tweaks, so this is what finally exercises the
      tweak accumulator (`tacc`) against external ground truth. Verified to be a real test:
      dropping the x-only tweak negation makes case 3 fail.
- [x] `sign_verify` (4 valid, 6 error) and `tweak` (5 valid, 1 error) transcribed and
      passing. **Every BIP327 vector group in `vectors.h` is now covered.**
- [x] The `tweak` group is what pins the accumulator *and* the parity flag together: a
      signer tracking one but not the other produces a partial signature that will not
      aggregate.
- [x] **`partial_sign` accepted a zeroed secret nonce.** BIP327 requires the rejection and
      upstream enforces it in `musig_secnonce_load`; here the `valid` flag caught ordinary
      reuse but not a secnonce that arrived zeroed by another route. Signing with k = 0
      makes s = e*d and hands the secret key to anyone who sees the partial signature, so
      it now fails on its own merits rather than only via the bookkeeping.
- [x] One error case is skipped, matching upstream verbatim: case 0 aggregates a key set
      not containing the signer's own key, and upstream's own comment says "the
      implementation does not error out when the signing key does not belong to any
      pubkey". Demanding a rejection there would invent a requirement the reference does
      not meet.

## 6. `scalar_low` for exhaustive mode

Upstream swaps the whole scalar representation under `EXHAUSTIVE_TEST_ORDER`: a scalar
becomes a single `uint32` mod the small order and `split_lambda` becomes plain modular
arithmetic. Ours is always 4x64 mod the real n, so the full tree does not build in
exhaustive mode.

- [x] Added `scalar/scalar_low.odin`, mirroring upstream's `scalar_low_impl.h`: a one-word
      `Scalar` with the identical public API, gated on `params.EXHAUSTIVE_ORDER > 0`. The
      4x64 files are gated on `== 0`, so exactly one representation is ever compiled.
      Shared definitions (`VERIFY`, `CHECK`, `ct_mask`) moved to `scalar_common.odin`,
      outside both gates.
- [x] Far less than the estimated ~1,000 lines. The 4x64 reduction did not need
      restructuring at all — the two implementations sit side by side rather than one being
      generalised, which is exactly what upstream does.
- [x] **The whole tree now builds under `-define:EXHAUSTIVE_ORDER`** — every package from
      `group` up through `musig`.
- [x] Added `tests/exhaustive/`, which enumerates the entire group rather than sampling:
      group structure, `ecmult_gen` for every scalar, `ecmult_const` for every
      (scalar, point) pair, variable-time `ecmult` for every (a, b, P) triple, and the
      scalar field over every pair. **Passes at orders 7, 13 and 199.**
- [x] **It immediately found a real gap.** `ecmult_const`'s `CONST_K` was stubbed to zero
      under exhaustive orders, with a note that small-order scalar arithmetic did not exist
      yet — so `ecmult_const` was wrong for every input. Now derived from upstream's
      formula as a compile-time constant expression, which also keeps it correct if
      `GROUP_SIZE` changes for a new order.

## 10. Start-up cost: generator tables

Found while looking for throughput. The variable-time engine's 1 MB of generator tables are
built when the process starts — about 12 ms — where libsecp256k1 compiles an equivalent
table into the binary. Steady-state benchmarks cannot see this, so it went unnoticed.

- [x] Measured: a one-shot sign+verify process takes **8 ms** with runtime tables and
      **1 ms** with them embedded. For a short-lived process the table build costs more than
      the cryptography.
- [x] Added `precompute_ecmult/`, which writes `ecmult/pre_g.bin`, and an embedded path
      behind `-define:SECP256K1_EMBED_TABLES=true` using `#load`. Odin has no arbitrary
      compile-time execution, so the compiler cannot *compute* the table; it can embed one.
      The blob is reinterpreted in place, not copied, so start-up is genuinely zero rather
      than a memcpy.
- [x] `tests/ecmult` recomputes **all 16,384 entries** from the curve definition and
      compares, in both modes. `CLAUDE.md`: "regeneration from scratch must reproduce
      byte-identical tables; that reproduction is a test."
- [x] The blob is generated, not committed — `.gitignore` excludes it — so the "nothing
      vendored" property in `ecmult_tables.odin` still holds.
- [x] **Made embedding the default**, matching what libsecp256k1 does: it commits
      `precomputed_ecmult.c`, a generated C source file holding the table as a
      `static const`, so the table lands in `.rodata` at compile time and the loader maps it
      from the binary. `ecmult/pre_g.bin` is therefore committed too — `#load` resolves at
      compile time, so a fresh clone must have it. 1.00 MB against upstream's 2.55 MB of
      generated C.
- [x] Two regressions caught while switching the default, both mine:
      **(a)** the embedded slices were package-level variables bound by Odin's runtime
      start-up, which a C program linking the static library never runs — `PRE_G` stayed
      empty and every lookup indexed out of range. `csuite` caught it. They are bound in
      `ensure_var_tables` now, the same fix `GENERATOR` needed earlier.
      **(b)** the blob holds real-curve points at the default window, so an exhaustive-order
      or non-default-`ECMULT_WINDOW_SIZE` build was silently multiplying against the wrong
      curve. Embedding now disables itself for those configurations.
- [ ] **Do not make the runtime build lazy without synchronization.** Attempted and reverted:
      deferring it to first use is a data race, because two threads can reach an unbuilt
      table together. Eager construction before any caller exists is what makes the
      unsynchronized ready-flags safe. A lazy version needs `sync.Once` or equivalent.

## 11. Drop-in C ABI — done

`capi/` originally exported 20 functions under `secp256k1_odin_*` names. It now exports the
**complete** upstream public API — all 75 functions plus every exported constant — under
upstream's own symbol names, with upstream's struct sizes and flag values.

- [x] Added the 55 missing entry points: the preallocated-context API, the illegal/error
      callbacks, pubkey combine/sort/cmp/negate, both seckey and pubkey tweaks, all of
      recovery, all of extrakeys, `schnorrsig_sign_custom`, all of ellswift, and all 17
      MuSig2 functions. Plus the exported function-pointer constants
      (`nonce_function_rfc6979`, `ecdh_hash_function_sha256`, and so on), which are data
      symbols, not functions.
- [x] Custom callbacks are genuinely wired, not stubbed. ECDSA's `noncefp`, ECDH's and
      ellswift's `hashfp`, and the illegal/error callbacks all reach C. The trampolines pack
      the C function pointer and user data into a struct passed as the internal `data`
      pointer, so they stay reentrant — a `proc "contextless"` cannot capture. The one
      exception is Schnorr's hardened nonce function, whose internal callback type has no
      user-data parameter; that one travels in a global and is documented as non-reentrant.
      Calls that use the *default* nonce function — which is every ordinary caller — never
      touch it and stay on the constant-time-verified path.
- [x] `schnorr.sign` gained an optional `noncefp`/`ndata`, mirroring upstream's
      `schnorrsig_sign_custom`. Existing call sites are unaffected; the parameters default
      to nil and the default path is byte-identical to before.
- [x] **Initialization under C linkage, properly.** `@(init)` never runs when linked into a
      C program, and `secp256k1_context_static` lets a caller reach the library without ever
      calling `context_create`. Every entry point now calls `ensure_ready`, a double-checked
      atomic guard — one relaxed load in the common case. The unsynchronized `*_ready` flags
      in `ecmult` are safe only because nothing can observe a half-built table, and this is
      what preserves that invariant when there is no Odin runtime start-up to rely on.
- [x] The six MuSig2 opaque blobs are packed to upstream's exact sizes (197/132/132/132/
      133/36), each with a distinct magic prefix so an uninitialized or wrong-typed blob is
      rejected rather than silently reinterpreted.
- [x] Headers rewritten as a full set matching upstream's — `secp256k1.h` plus the six
      module headers, replacing the single `secp256k1_odin.h`. CI checks that a consumer
      compiled against ours and against upstream's produces identical output.

### It found a real bug the oracle could not

`dropin/run.sh` compiles one unmodified C consumer twice, against each archive, and diffs.
On the first run, exactly one of 61 lines differed: `ellswift_encode`.

BIP324 specifies the candidate stream as `H(pubkey || "\x00"*31 || rnd32 || cnt)`. This
implementation was hashing the bare 33-byte serialization with no padding. The encoding it
produced was *valid* — `decode` returns the original key, so the round-trip test passed —
but no other implementation derives it from the same randomness, which is the entire
property `rnd32` exists to provide. This is the same class of defect, in the same module,
that item 2 recorded for `ellswift_create`.

The differential oracle had a binding for `ellswift_encode` and never called it. Fixed, and
`test_oracle_ellswift_encode` now closes the gap — verified to fail against the old code, so
it is not vacuous.

## 12. `csuite` stack overflow — fixed

`csuite_layout` writes nine `u64`s; `test_csuite.c` declared and passed an array of eight.
The Odin side wrote eight bytes past the end of a C stack array on every run, and the only
symptom was the stack protector aborting on return — after the output had been printed and
lost to buffering, which is why it looked like a hang rather than a smash.

- [x] C side widened to nine, with the count in a `#define` so the two cannot drift again.
- [x] `csuite/build.sh` now compiles with `-Wall -Wextra -fstack-protector-strong`, so this
      class of mismatch fails loudly everywhere rather than only where the platform happens
      to enable the protector by default.
